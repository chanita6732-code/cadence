# Cadence — Habit Tracker

เว็บติดตามนิสัยประจำวัน ดู Streak สถิติ และตั้งเป้าหมาย รองรับการล็อกอิน (Google หรืออีเมล) และซิงก์ข้อมูลข้ามอุปกรณ์แบบเรียลไทม์ ใช้งานออฟไลน์ได้ และติดตั้งเป็นแอปบนมือถือได้ (PWA)

- **ไม่มีข้อมูลตัวอย่าง** ทุกตัวเลขและกราฟคำนวณจากสิ่งที่ผู้ใช้บันทึกจริง
- **บันทึกลงเครื่องก่อน แล้วค่อยซิงก์ขึ้น cloud** จึงใช้งานได้ลื่นแม้เน็ตช้าหรือไม่มีเน็ต
- **ไม่โหลดอะไรจาก CDN** ไลบรารีและฟอนต์อยู่ในโฟลเดอร์ `vendor/` ทั้งหมด

- **ภาษาไทย / English** เลือกได้ที่หน้า Settings หรือปุ่มมุมขวาบนของหน้าเข้าสู่ระบบ
  ถ้าเครื่องตั้งภาษาไทยไว้ จะเปิดเป็นภาษาไทยให้อัตโนมัติ

---

## เริ่มใช้งานเร็วที่สุด (ยังไม่ต้องมีระบบล็อกอิน)

ดับเบิลคลิก `index.html` แอปจะทำงานในโหมด **"This device only"** คือเก็บข้อมูลไว้ในเบราว์เซอร์เครื่องนี้เท่านั้น

ถ้าต้องการให้คนอื่นใช้และล็อกอินข้ามอุปกรณ์ได้ ให้ทำ 2 ขั้นด้านล่าง

---

## 1. ตั้งค่า Firebase (ฟรี, แผน Spark ไม่ต้องใส่บัตรเครดิต)

1. **สร้างโปรเจกต์:** ไปที่ <https://console.firebase.google.com> → **Create a project**
   - ตั้งชื่อ เช่น `cadence`
   - Google Analytics ปิดได้
2. **เปิดฐานข้อมูล:** เมนู **Build → Firestore Database → Create database**
   - Location เลือก `asia-southeast1 (Singapore)`
   - เลือก **Start in production mode**
3. **ใส่กฎความปลอดภัย:** แท็บ **Rules** ลบของเดิมทิ้ง วางเนื้อหาไฟล์ `firestore.rules` ทั้งไฟล์ แล้วกด **Publish**
   - กฎนี้ทำให้แต่ละคนอ่านและเขียนได้เฉพาะข้อมูลของตัวเอง และตรวจรูปแบบข้อมูลทุกครั้งที่เขียน
4. **เปิดระบบล็อกอิน:** เมนู **Build → Authentication → Get started → Sign-in method**
   - เปิด **Google**: เลือกอีเมลติดต่อ แล้ว Save
   - เปิด **Email/Password**: เปิดเฉพาะตัวบน ไม่ต้องเปิด passwordless
5. **เอาค่า config มาใส่:** ไปที่ **⚙️ Project settings → General → Your apps** → กดไอคอน **`</>`** (Web)
   - ตั้งชื่อแอป แล้วกด Register (ไม่ต้องติ๊ก Firebase Hosting)
   - คัดลอกค่าใน `firebaseConfig` มาใส่ใน `config.js`:

   ```js
   window.CADENCE_CONFIG = {
     firebase: {
       apiKey: 'AIza...',
       authDomain: 'cadence-xxxx.firebaseapp.com',
       projectId: 'cadence-xxxx',
       storageBucket: 'cadence-xxxx.firebasestorage.app',
       messagingSenderId: '1234567890',
       appId: '1:1234567890:web:abcdef',
     },
   };
   ```

   ค่าเหล่านี้เปิดเผยได้ตามการออกแบบของ Firebase เพราะความปลอดภัยมาจาก `firestore.rules`
   **ห้ามใส่ไฟล์ service account (JSON ของ Admin SDK) ลงในเว็บเด็ดขาด**

## 2. นำเว็บขึ้นโฮสต์

เว็บนี้เป็นไฟล์ static ล้วน อัปโหลดทั้งโฟลเดอร์ได้เลย ไม่ต้อง build

| วิธี | ขั้นตอน |
|---|---|
| **GitHub Pages** | push ขึ้น repo → Settings → Pages → เลือก branch |
| **Firebase Hosting** | `npx firebase-tools login` แล้ว `npx firebase-tools deploy --project <project-id>` (มี `firebase.json` ให้แล้ว) |
| **Netlify Drop** | ลากโฟลเดอร์นี้ไปวางที่ <https://app.netlify.com/drop> |

**สำคัญ: อนุญาตโดเมนให้ล็อกอินได้**
- ไปที่ **Authentication → Settings → Authorized domains → Add domain** แล้วใส่โดเมนของเว็บ เช่น `your-name.github.io`
- ถ้าใช้ Firebase Hosting ไม่ต้องทำขั้นนี้ เพราะโดเมนถูกเพิ่มไว้ให้อัตโนมัติ

**ติดตั้งเป็นแอป:** เปิดเว็บบนมือถือ แล้วเลือก *Add to Home Screen* (iOS: ปุ่ม Share, Android: เมนู ⋮)

### ทดสอบบนเครื่องตัวเอง

ปุ่ม "Continue with Google" และ Service Worker ใช้ได้เฉพาะเมื่อเปิดผ่าน `http(s)` เท่านั้น:

```bash
python3 -m http.server 8080   # แล้วเปิด http://localhost:8080
```

`localhost` อยู่ใน Authorized domains ตั้งแต่แรกอยู่แล้ว

### เมื่ออัปเดตเว็บ

เปลี่ยนเลข `CACHE` ใน `sw.js` (เช่น `cadence-v2.3.1`) ทุกครั้งที่ deploy เวอร์ชันใหม่ ผู้ใช้จะได้ไฟล์ใหม่ในการเปิดครั้งถัดไป

## โควตาฟรีของ Firebase (แผน Spark)

| รายการ | ฟรีต่อวัน |
|---|---|
| อ่านข้อมูล | 50,000 ครั้ง |
| เขียนข้อมูล | 20,000 ครั้ง |
| พื้นที่ | 1 GB |

ต่อวันแอปนี้อ่านเฉพาะข้อมูลที่เปลี่ยนแปลง ไม่ได้อ่านใหม่ทั้งหมดทุกครั้งที่เปิด โควตาฟรีจึงรองรับผู้ใช้ได้หลายร้อยคน
ถ้าใช้เกินโควตา การซิงก์จะหยุดชั่วคราวจนถึงวันถัดไป แต่ข้อมูลไม่หายและยังบันทึกในเครื่องได้ตามปกติ
และไม่มีการเก็บเงินเพิ่ม เพราะแผน Spark ไม่ได้ผูกบัตรเครดิตไว้

## การทำงานของข้อมูล

### ประเภทการติดตาม Habit

ตอนสร้างหรือแก้ไข Habit เลือก **วิธีติดตาม** ได้ 4 แบบ:

| ประเภท | ใช้กับ | หน่วย |
|---|---|---|
| ทำ / ไม่ทำ | แปรงฟัน, เก็บห้อง | ติ๊กอย่างเดียว (แบบเดิม) |
| เวลา | นอน, อ่านหนังสือ, ออกกำลังกาย | ชม., นาที |
| จำนวน | ดื่มน้ำ, ทำโจทย์, วิดพื้น | ครั้ง, หน้า, แก้ว, ข้อ หรือพิมพ์หน่วยเอง |
| ระยะทาง | เดิน, วิ่ง | กม., ม. |

- Habit แบบวัดค่ามี **เป้าหมายต่อวัน** และแต่ละวันบันทึก **ค่าที่ทำจริง**
- เปอร์เซ็นต์ = ค่าที่ทำจริง ÷ เป้าหมาย × 100 (ปัดลง) แถบ Progress แสดงไม่เกิน 100% แต่ค่าจริงเก็บไว้ครบ
- ระดับมาตรฐาน: 0–39% ต่ำมาก, 40–69% ต่ำ, 70–89% ใกล้เป้าหมาย, 90–99% เกือบถึงเป้าหมาย, 100%+ สำเร็จ
- Habit แบบเวลาเลือก **เกณฑ์การนอน** ได้ ซึ่งประเมินตามชั่วโมงเทียบกับเป้า:
  ขาดเกิน 2 ชม. = น้อยมาก, ขาด 2 ชม. = น้อย, ขาด 1 ชม. = พอใช้, ถึงเป้า = ดี, เกิน 1 ชม. ขึ้นไป = ดีมาก
  (เกณฑ์อยู่ในฟังก์ชัน `evaluate()` ใน `script.js` เพิ่มเกณฑ์ของ Habit อื่นได้ที่เดียวกัน)
- บันทึกแต่ละวันเก็บ **เป้าหมาย ณ วันนั้น** ไว้ด้วย แก้เป้าหมายทีหลังแล้วประวัติเก่าไม่เปลี่ยน
- Habit เดิมที่ไม่มีประเภทถือเป็นแบบ "ทำ / ไม่ทำ" และเปลี่ยนประเภทภายหลังได้โดยประวัติไม่หาย

### กติกาการคำนวณ

- **Habit ถูกนับในวันไหน:** วันนั้นต้องอยู่หลังวันเริ่ม, ตรงกับวันในสัปดาห์ที่ตั้งไว้, และไม่อยู่ในช่วงที่พัก Habit
  ใช้กติกาเดียวกันทุกจุด ทั้ง Rate, Streak, Total, Goal และ Weekly target
- **Completion rate** = คะแนนรวม ÷ (ต้องทำ − ข้าม) โดย Habit ที่ทำแล้วได้ 1 คะแนน ส่วน Habit แบบวัดค่าได้คะแนนตามสัดส่วนที่ทำได้ (ไม่เกิน 1) การกด "ข้าม" ไม่ทำให้ % ลดลง
- **"ทำแล้ว"** ของ Habit แบบวัดค่า หมายถึงทำได้ถึงเป้าหมายของวันนั้น ใช้นับ Streak ของ Habit, Goal ที่ผูกไว้ และยอดรวม
- **วันที่นับเข้า Streak:** ต้องทำได้ ≥ เกณฑ์ที่ตั้ง (ค่าเริ่มต้น 80%, เปลี่ยนได้ใน Settings)
  - วันที่ไม่มี Habit ให้ทำไม่นับและไม่ตัด Streak
  - วันนี้ที่ยังทำไม่ครบไม่ตัด Streak
- **Best habit:** ต้องมีการเช็กอินอย่างน้อย 5 ครั้งในช่วงที่เลือก จึงจะถูกจัดอันดับ
- **พัก Habit:** ประวัติก่อนหน้ายังนับตามปกติ และช่วงที่พักไม่ถูกนับว่าพลาด

### การซิงก์

- การเปลี่ยนแปลงบันทึกลงเครื่องทันที แล้วส่งขึ้น Firestore เป็นชุด
- อุปกรณ์อื่นได้รับการเปลี่ยนแปลงแบบ**เรียลไทม์** ไม่ต้องรีเฟรช
- ออฟไลน์อยู่: การเปลี่ยนแปลงเข้าคิวไว้ พอเน็ตกลับมาก็ส่งเอง แม้จะปิดแล้วเปิดเว็บใหม่ระหว่างนั้น
- ถ้าสองเครื่องแก้ช่องเดียวกันพร้อมกัน **เครื่องที่ซิงก์ทีหลังชนะ** และทุกเครื่องจะได้ค่าเดียวกัน
- สถานะการซิงก์แสดงที่มุมซ้ายล่าง (มือถือแสดงเป็นจุดสีบนหัวเว็บ):
  - 🟢 ซิงก์แล้ว
  - 🟣 กำลังซิงก์
  - 🟠 ออฟไลน์
  - 🔴 มีปัญหา (ระบบจะลองใหม่อัตโนมัติ)

### โครงสร้างข้อมูลใน Firestore

```
users/{uid}                          ชื่อ + การตั้งค่า
users/{uid}/habits/{habitId}         ลบแล้วจะมี deleted = true
users/{uid}/goals/{goalId}           ลบแล้วจะมี deleted = true
users/{uid}/logs/{habitId}_{date}    status = done | skipped | null, value + target (Habit แบบวัดค่า)
```

### ความปลอดภัย

- ข้อมูลทุกชิ้น ทั้งจากเครื่อง, ไฟล์ Import และ server ต้องผ่านการตรวจชนิดข้อมูลก่อนใช้ และข้อความทุกชิ้นถูก escape ก่อนแสดงผล
- `firestore.rules` ตรวจชุดเดียวกันซ้ำที่ฝั่ง server และบังคับให้ `updatedAt` เป็นเวลาของ server
- **Sign out** จะลบสำเนาข้อมูลในเครื่อง ข้อมูลยังอยู่ในบัญชี
- **Delete account** ลบบัญชีและข้อมูลทั้งหมด
  Firebase กำหนดให้ต้องล็อกอินมาไม่เกินไม่กี่นาทีก่อนลบ แอปจะบอกขั้นตอนเองถ้าจำเป็น
- ถ้าข้อมูลในเครื่องเสียหาย ระบบจะ**เก็บสำเนาไว้แทนการเขียนทับ** และดาวน์โหลดได้จาก Settings

### Backup

- **Settings → Export backup** ได้ไฟล์ JSON
- **Import backup** จะแทนที่ข้อมูลปัจจุบัน ถ้าล็อกอินอยู่จะแทนที่บนทุกอุปกรณ์

## โครงสร้างไฟล์

```
index.html              โครงหน้าเว็บ ทุกหน้าและทุกหน้าต่าง
style.css               ธีมม่วง–กรม, dark/light, responsive
script.js               ตรรกะทั้งหมด (แบ่ง 14 ส่วน ดูสารบัญบนสุดของไฟล์)
config.js               ใส่ค่า Firebase ที่นี่
i18n.js                 ข้อความภาษาอังกฤษ / ไทย ทั้งหมด (แก้คำแปลที่นี่)
firestore.rules         กฎความปลอดภัยของฐานข้อมูล
firebase.json           สำหรับ Firebase Hosting / Emulator (ไม่บังคับ)
sw.js                   Service Worker (ใช้งานออฟไลน์)
manifest.webmanifest    ข้อมูลสำหรับติดตั้งเป็นแอป
icons/                  ไอคอนแอป
vendor/                 Chart.js, Firebase SDK, ฟอนต์ Inter + Noto Sans Thai (พร้อมไฟล์ LICENSE)
```

### สำหรับนักพัฒนา: ทดสอบกับ Firebase Emulator

```bash
npx firebase-tools emulators:start --only auth,firestore --project demo-cadence
```

แล้วเพิ่มใน `config.js` เพื่อชี้ไปที่ emulator (ห้ามใช้บนเว็บจริง):

```js
emulator: { host: '127.0.0.1', authPort: 9099, firestorePort: 8080 },
```
